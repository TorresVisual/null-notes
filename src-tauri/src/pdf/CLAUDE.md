## The PDF pipeline

No OCR. A typeset PDF carries its own text layer, and reading it is exact where recognising pixels would only ever be a guess.

`layout.rs` reconstructs document structure (lines, blocks, headings, code, lists, emphasis) from plain `CharBox` values and **must not gain a pdfium dependency**. Nothing in CI has the pdfium native library — the render tests are `#[ignore]`d for that reason — so a pdfium-free module is the only part of this pipeline that can actually be tested. `extract.rs` is the translation layer: it turns pdfium types into `CharBox` and makes no decisions. Put judgement in `layout`, plumbing in `extract`.

Use `loose_bounds()`, not `tight_bounds()` — tight bounds cover a glyph's inked extent, so gap-based space detection fires after every comma. pdfium is synchronous, so page work belongs in `spawn_blocking`.

Two things about pdfium that cost real debugging time:

- It injects **synthetic characters** describing the text layer's own structure (CR/LF at every line end, spacing markers). They report a font size of 1.0 with zero bounds, and are identified by an **empty font name** — real glyphs always have one. Keeping them drags a row's median font size to 1.0 and collapses the baseline tolerance, which shreds the whole document.
- It binds its library **once per process**, not once per call — `bind_pdfium()` on the *second* PDF imported in a running session answers `PdfiumLibraryBindingsAlreadyInitialized` rather than returning the bindings. Treat that as success (`Pdfium::default()` reuses the live bindings), never as "pdfium not found".

Equations are rebuilt as LaTeX, not cropped — a cropped image can't be pasted into a prompt, searched, or edited, and doesn't render through the editor's own KaTeX nodes. A LaTeX PDF contains no LaTeX either, but which face a glyph came from carries most of its meaning: `maths.rs` classifies the face (`CMMI` a variable, `CMSY` a relation, `MSBM` blackboard bold, …), and `latex.rs` turns face plus geometry into text — smaller and off-baseline is a script, consecutive upright letters are an operator name. A maths region is a direct slice of the page's character row, so it bypasses `layout.rs`'s own gap-based space synthesis and has to redo it locally against the same `SPACE_GAP`. A footnote marker and a real exponent are the same geometry (raised, reduced size); the only distinguishing signal is that an exponent never follows terminal punctuation. `throwOnError: false` on both maths nodes means a bad equation renders its own KaTeX error rather than breaking anything around it.

Glyphs are not the only input. A fraction bar is a **drawn rule**, not a character, so it never reaches the text layer — and it is the only record of how many fraction terms a row carries and where each one begins. `rules.rs` holds that geometry (pdfium-free, like `columns.rs`; `extract.rs` translates `PdfPageObject::Path` into it), and `reconstruct_ruled_fractions` uses each bar's x-span to split a row of side-by-side fractions that the older gap-ranking passes can only guess at. Take rule geometry from `bounds()`, never `segments()` — pdfium reports segment coordinates in the path's own object space, so a full-width page rule reads `0,0 → 595.3,0` wherever it actually sits. A bar's span alone cannot tell a fraction bar from page furniture, because a full-width separator's span contains every prose row on the page; width relative to the surrounding content is what separates them.

Judging this pipeline means looking at real output: `dump.rs` holds `#[ignore]`d diagnostics driven by `NULL_NOTES_PDF`. Every bug found so far was invisible in synthetic fixtures.

**The pipeline is frozen** (roadmap §P4-2e). The ten sheets in `notes/exercise_sheets/` are the regression suite and adding one is a deliberate decision. The PDFs are gitignored, but their expected Markdown is committed in `src-tauri/tests/pdf_golden/` and `golden.rs` diffs against it when `NULL_NOTES_PDF_DIR` is set (`NULL_NOTES_PDF_UPDATE=1` regenerates; review the golden diff in the same commit as the fix). A new bug earns work only if it is whole-document — silent prose loss, mid-word tearing — or recurs across two or more of them; single-document cosmetic bugs get recorded in `TODO.md` under "Filed, not fixed" and left. 2D-layout reconstruction is closed: matrices, `\cases`, stacked fractions, operator limits, tables and ruled fractions are the complete set, and anything else renders as glyph-order text. `exercises.rs` is the one part still open to change, and it works on the assembled Markdown rather than on `Block`s because an exercise spans page breaks while blocks exist one region at a time.
