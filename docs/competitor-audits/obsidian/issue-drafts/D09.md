# Let users rebind keyboard shortcuts

## Summary
A shortcuts section in Settings to view, change, clear and reset the key binding for any command.

## Problem
Shortcuts are hard-coded; Ctrl+P, Ctrl+K, Ctrl+Shift+P and others cannot be changed, and conflicts with the OS or a non-US layout cannot be worked around.

## Competitor reference
[Hotkeys](https://obsidian.md/help/hotkeys) let users assign, change, remove and filter hotkeys for every command, with a list of defaults.

## Current behavior
`Layout.tsx:502-526` is a literal `KEY_COMMANDS` map; accelerators are also hard-coded as labels in `Titlebar.tsx`, `CommandPalette.tsx` (`EXTRA_ACTIONS`) and `ShortcutsOverlay.tsx`. `AppSettings` has no keymap field.

## Expected behavior
Settings lists every command with its binding, lets the user record a new one, warns on conflicts and resets to defaults; menus, palette and the shortcut sheet show the effective binding.

## Acceptance criteria
- [ ] A Shortcuts section lists all command ids with current bindings and a search field
- [ ] Recording a key combo rebinds it; conflicts are flagged and block saving
- [ ] Clear and Reset (single command and all) work
- [ ] Layout, Titlebar menus, CommandPalette and ShortcutsOverlay read from the same keymap, so labels never go stale
- [ ] Bindings persist across restarts
- [ ] Reserved keys (Ctrl+C/V/X/Z, Tab, etc.) cannot be bound

## Scope
**In:** Rebinding of existing commands.

**Out (track separately):** New commands, Vim/Emacs keymaps, chord sequences.

## Implementation considerations
Machine-local preference: store in `settings.json` in the OS app-data dir (CLAUDE.md storage boundary). Unify the four hard-coded lists into one registry first.

## Priority
P3. Matters mainly for people whose layout or habits clash with the fixed set; now cheaper because the action palette gives every command an id.
