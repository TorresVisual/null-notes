# Bookmarks: pin notes, headings and saved searches in the sidebar

## Summary
Let the user bookmark notes, folders, headings and `folder:`/`tag:`/`type:` searches, grouped in a sidebar section.

## Problem
The only ways back to a note are the tree, Ctrl+P and search. A student with 15 course folders cannot keep "this week's sheet" or "all #exam notes in Algo" one click away, and filters typed in Ctrl+K are lost.

## Competitor reference
[Bookmarks](https://obsidian.md/help/plugins/bookmarks) save files, folders, graphs, searches, headings and blocks, with optional groups.

## Current behavior
No bookmark or favourite concept exists. Search filters are parsed by `lib/searchQuery.ts` but never stored; the tree (`Sidebar.tsx`, `FolderTree.tsx`) has no pinned section.

## Expected behavior
A Bookmarks section in the sidebar lists items; clicking a note/heading opens it, clicking a search re-runs it; items can be grouped, reordered and removed.

## Acceptance criteria
- [ ] Add bookmark from a note's context menu/palette, a heading, and from the search modal ("save this search")
- [ ] Clicking opens the note (scrolling to the heading) or re-runs the saved search
- [ ] Bookmarks follow renames and moves; deleting a note marks its bookmark as missing instead of silently dropping it
- [ ] Groups and drag-reorder
- [ ] Bookmarks survive restart and, if stored in the workspace, merge cleanly under Git

## Scope
**In:** Bookmarks for notes, folders, headings and saved searches.

**Out (track separately):** Bookmarking graphs/blocks, a query language or database views.

## Implementation considerations
Decide the column first (CLAUDE.md "storage boundary"; ROADMAP §1): bookmarks are user content that arguably should travel with the notes (a small workspace file whose format merges well, e.g. one entry per line), unlike `.workspace.json`, which is gitignored UI state. Note identity is the path, so `rename_note_at` / `move_note` must update bookmarks the way they update links.

## Priority
P2. Gives course-level quick access without a query language, the cheap answer to Obsidian Bases that the roadmap prefers (ROADMAP §4).
