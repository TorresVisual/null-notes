# Callouts: foldable ([!type]+/-) and the remaining Obsidian callout types

## Summary
Interpret `+`/`-` after a callout type as collapsible (open/closed) and recognise the rest of Obsidian's callout types without losing the original type name.

## Problem
`> [!note]- Title` becomes a callout whose title is "- Title" and cannot collapse; `> [!question]`, `[!bug]`, `[!success]` and similar stay as plain blockquotes.

## Competitor reference
[Callouts](https://obsidian.md/help/callouts) document foldable callouts (`+`/`-`), a custom title and the supported types and aliases.

## Current behavior
`src/editor/extensions/Callout.tsx:160` matches only NOTE, TIP, WARNING, DANGER, INFO, IMPORTANT and the STEM types; the text after `]` (including `+`/`-`) is taken as the title. `Details.tsx` is a separate collapsible node.

## Expected behavior
Fold markers set a collapsed/expanded state that the user can toggle; every `[!type]` is a callout, with known types styled and unknown ones using a neutral style and keeping their type string.

## Acceptance criteria
- [ ] `[!type]-` renders closed and `[!type]+` renders open, both toggleable; the marker is written back unchanged
- [ ] Types abstract, todo, success, question, failure, bug, quote (and aliases) are recognised with distinct icons/colours from the design tokens
- [ ] An unknown type round-trips unchanged
- [ ] Existing STEM callouts, numbering (`CrossRef.ts`) and #102 flashcard conversion are unaffected
- [ ] Tests in `Callout` markdown round-trip

## Scope
**In:** Fold markers and type coverage.

**Out (track separately):** Custom callout CSS/plugins, nested-callout redesign.

## Implementation considerations
Add a `foldable` attribute (open/closed/null) and keep the raw type string; follow `docs/design-tokens.md` for colours. Reuse the open/closed UI from `Details.tsx` where possible.

## Priority
P3. Only matters for notes shared with or imported from Obsidian; content is not lost today but renders wrongly.
