# Notes have no context menu: duplicate, show in Explorer, copy path, move to...

## Summary
Right-clicking a note (in the tree or on its tab) offers Duplicate, Show in File Explorer, Open in default app, Copy path and Move to... alongside Rename and Delete.

## Problem
Note rows only have hover buttons for rename and delete. To copy a note, find it on disk, or move it without dragging, the student has to leave the app or drag across a long tree.

## Competitor reference
The [File explorer](https://obsidian.md/help/plugins/file-explorer) context menu lists Duplicate, Move file to..., Copy path, Reveal in Filesystem and Open in default app; the [More options menu](https://obsidian.md/help/more-options-menu) repeats them per note.

## Current behavior
`TreeNode.tsx` renders inline Rename/Delete buttons for notes (lines ~106-121) and uses the shadcn `ContextMenu` only for folders (:243). `tauri-plugin-opener` is a dependency with `opener:default` in `capabilities/default.json`, but nothing in `src/` calls it for notes. `notes.rs` has `move_note` (:2342) and `rename_note` (:1509) but no duplicate.

## Expected behavior
A note context menu with the five actions; Duplicate copies the `.md` and its `.ink/.pdf/.diagrams/.assets` sidecars under a new unique name.

## Acceptance criteria
- [ ] Right-click on a note row and on a tab shows Duplicate, Show in File Explorer, Open in default app, Copy path, Move to..., Rename, Delete
- [ ] Duplicate creates "Name copy" (next free name), copies all four sidecar folders and rewrites sidecar paths inside the copy (as rename does, #17); the copy gets a distinct title so it does not collide with the original (#122)
- [ ] Move to... opens a folder picker and reuses `move_note`
- [ ] Show in File Explorer / Open in default app use the opener plugin on a path validated to be inside the workspace
- [ ] Copy path offers absolute and workspace-relative
- [ ] Actions appear in the command palette for the active note

## Scope
**In:** Per-note context menu and the five actions.

**Out (track separately):** Multi-select bulk operations (#124), Explorer shell integration (#25), OS trash behaviour (#121).

## Implementation considerations
Follow `src-tauri/src/commands/CLAUDE.md`: never take the program or an arbitrary path from the frontend; validate paths against the workspace root as the other note commands do (issue #5). Duplicating must keep the save-path rules (write_atomic) and update the index.

## Priority
P2. File-management basics that every file explorer offers; the opener plugin is already installed, so the gap is UI and a couple of commands.
