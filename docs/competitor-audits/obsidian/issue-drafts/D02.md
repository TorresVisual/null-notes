# Search: support exact phrases, OR, exclusion and grouping

## Summary
Let a query use `"exact phrase"`, `a OR b`, `-term` and parentheses, alongside the existing `folder:`, `tag:` and `type:` filters.

## Problem
A student searching "binary tree -heap" or "\"master theorem\" OR \"recurrence\"" cannot express it. Quotes are stripped, so a phrase matches its words anywhere in any order, and "OR" is searched as a literal word.

## Competitor reference
[Search](https://obsidian.md/help/plugins/search) documents exact phrases, `OR`, `-` exclusion and parenthesised groups, e.g. `meeting (work OR meetup) personal`.

## Current behavior
`search_notes` (`src-tauri/src/commands/notes.rs:1663-1672`) splits the query on whitespace and rebuilds it as `"w1"* "w2"*` (implicit AND, prefix match), removing every `"`. `src/lib/searchQuery.ts` only extracts `folder:`, `tag:` and `type:`.

## Expected behavior
The query box understands quoted phrases, OR, a leading minus and parentheses; operators combine with the existing filters; malformed input never errors.

## Acceptance criteria
- [ ] `"exact phrase"` matches only notes containing the words adjacently, in order
- [ ] `a OR b` returns notes containing either term
- [ ] `a -b` excludes notes containing `b`; `-"x y"` excludes a phrase
- [ ] `a (b OR c)` groups correctly
- [ ] Unbalanced quotes or parentheses degrade to a plain search instead of failing
- [ ] Prefix matching of the last bare word is preserved
- [ ] Combines with `folder:`/`tag:`/`type:`; unit tests in `searchQuery.test.ts` and a Rust test for the FTS expression

## Scope
**In:** Query syntax for phrase/OR/NOT/grouping.

**Out (track separately):** Regex and case-sensitive matching, `line:`/`block:`/`section:` operators, `task:` (#55), nested-tag matching (#107).

## Implementation considerations
FTS5 supports phrases, OR, NOT and parentheses natively; the current code quotes every token to avoid FTS syntax errors. Add a small parser that emits only a safe FTS5 expression (escape quotes, drop unbalanced groups). Keep it in Rust next to `search_notes` or share with `searchQuery.ts`; do not pass raw user text to MATCH.

## Priority
P2. Search is the main recall tool at course volume; today every query is an AND of prefix terms, so narrowing or widening is impossible.
