# Embed a note or heading inside another note

## Summary
Render `![[Note]]` and `![[Note#Heading]]` as a live, read-only excerpt of the target inside the current note.

## Problem
To reuse a definition or worked example in several notes the student must copy and paste it, and the copies drift.

## Competitor reference
[Embed files](https://obsidian.md/help/embeds) show a note, or a heading of it, inline and keep it up to date.

## Current behavior
No embed node exists; `![[` is not handled anywhere in `src/editor/extensions/`. Images use standard Markdown syntax (`NoteImage.tsx`).

## Expected behavior
An embed node shows the target's current content read-only, with a header linking to the source; edits happen in the source note.

## Acceptance criteria
- [ ] `![[Note]]` and `![[Note#Heading]]` render the target content inline and update when it changes
- [ ] Cycles (A embeds B embeds A) render a placeholder instead of recursing
- [ ] Unresolved embeds show a muted placeholder like unresolved wiki-links
- [ ] The file on disk keeps the `![[...]]` text; round-trip is lossless
- [ ] Backlinks count an embed as a link

## Scope
**In:** Read-only note/heading embeds.

**Out (track separately):** Block references and `^id` markers, embedding other file types, live `query` blocks (ROADMAP §4), editing in place.

## Implementation considerations
Decide first, in a short ADR, whether the added syntax is acceptable: `[[ ]]` is already non-standard, but `![[ ]]` will not render on GitHub (see #113). Depends on D04 for heading anchors. Rendering needs the existing Markdown pipeline on a second note and a cycle guard.

## Priority
P3. Useful for assembling a revision sheet from existing notes, but it adds non-portable syntax; the roadmap already flags it as low priority.

## Category
Advanced
