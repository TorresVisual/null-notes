# Extract selected text into a new note, and merge two notes

## Summary
Add "Extract selection to new note" (leaves a link behind) and "Merge into another note" with link and sidecar rewriting.

## Problem
Splitting a 600-line lecture note or folding two overlapping notes together means copy/paste, then fixing links, ink/diagram/asset sidecars and card state by hand.

## Competitor reference
[Note composer](https://obsidian.md/help/plugins/note-composer) merges a note into another (updating links) and extracts a selection into a new or existing note.

## Current behavior
No merge/extract command exists in `notes.rs`. Related building blocks: `rename_note_at` (link rewriting), `move_note`, sidecar path rewriting (#17) and `splitIntoTasks.ts` (a purpose-specific splitter).

## Expected behavior
Extract: pick destination (new or existing), selected blocks move, a `[[link]]` replaces them. Merge: append source to destination and make links to the source point at the destination.

## Acceptance criteria
- [ ] Extract moves the selection (including ink/diagram/image blocks and their sidecar files) into a new note and leaves a wiki-link
- [ ] Merge appends the source to the destination, moves its sidecars, rewrites links to the source, and sends the source to Trash (#121)
- [ ] Flashcards and `sr` state in moved blocks keep working
- [ ] Undo restores the previous state (trash + toast), nothing is lost on failure
- [ ] All writes use write_atomic; reindex runs after

## Scope
**In:** Extract and merge for notes with sidecars.

**Out (track separately):** Template-driven composition, merging more than two notes at once.

## Implementation considerations
Sidecar folders are named after the note, so moved blocks must have their `src` paths rewritten and files copied; use the same rewrite path as rename. Needs the Trash work (#121) for the merged source.

## Priority
P3. Reorganising notes is a periodic need (long lecture notes, exercise sheets); doable by hand today but error-prone because links and sidecars must follow.
