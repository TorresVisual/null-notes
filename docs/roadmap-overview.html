Product & feature map — 2026-08-19

null-notes

A Markdown-first, WYSIWYG desktop note app for a CS student who writes math and code daily, sketches diagrams by hand, and never wants their notes locked into a proprietary format. Notion's editor, on Obsidian's storage model.

Tauri 2 Rust React 19 + TS TipTap 3 SQLite FTS Windows-primary Single user, offline-first CI + e2e on push

Non-negotiable principles

Established early, still governing every decision below. Any future feature has to fit inside these, not around them.

01

Plain .md is the source of truth. SQLite is a rebuildable index — deleting it loses nothing.

02

Offline-first, local-first. No cloud dependency to open a note, ever.

03

The file on disk is always safe. No edit path may silently lose or corrupt a note.

04

Small, sharp feature set. Three similar things is not a pattern; no scaffolded half-features.

— Foundation

Built before the phase roadmap existed and never revisited because it hasn't needed to be — the editor and ink subsystems are the mature heart of the app.

  • WYSIWYG Markdown editor — live-preview, plain .md as the only file format, full GitHub-flavored Markdown.
  • Maths, diagrams, code — KaTeX (inline + block), Mermaid diagrams, syntax-highlighted code blocks, callouts, tables, task lists.
  • Wiki-links & backlinks — [[links]] with a backlinks panel, plus #tags and a tag browser.
  • Full-text search — SQLite FTS over every note, Ctrl+K, scoped per workspace.
  • Inline handwriting — vector ink blocks with pen/eraser/shapes, pressure sensitivity, palm rejection.
  • Folder tree — create/rename/delete with cascade, drag-to-move.
  • Session persistence — open tabs and expanded folders remembered per workspace.
  • "Terminal Precision" design system — the app's own visual identity and icon set.
  • End-to-end test harness — WebdriverIO + tauri-driver against the real compiled app, screenshot-verified, run in CI on every push alongside fmt/clippy/unit tests.

P0 Trustworthy daily driver shipped

Milestone: I trust it with my real notes. Every later feature that touches a note write is bound by the rules this phase established.

  • Debounced autosave — typing never triggers a per-keystroke write; a visible clean / dirty / saving / error indicator tracks state.
  • Crash-safe writes — temp file → fsync → rename, so a killed process never leaves a half-written note.
  • Save/index split — the file write is the fast path; search/tag/link reindexing runs on a slower debounce.
  • External-change watcher — a file edited elsewhere (another editor, git pull, Syncthing) refreshes the tree and index automatically; a dirty buffer gets a conflict prompt instead of being overwritten.

P1–P2 Everyday use & ergonomics shipped

Milestones: I don't reach for another app and it's a pleasure to use for hours.

  • Click-to-create links — an unresolved [[wiki-link]] creates and opens the note.
  • Quick switcher — Ctrl+P fuzzy-jumps to any note; recent workspaces replace the folder dialog on reopen.
  • Link-preserving rename — renaming a note rewrites every inbound [[link]] across the workspace.
  • Settings panel — autosave delay, editor width, spellcheck + language, editor/terminal commands.
  • Native menu + shortcuts — File/Edit/View menu, a discoverable shortcut overlay (?).
  • Editor niceties — paste/drop images into a note, cursor & scroll position remembered per tab, list editing that doesn't tear apart on Backspace.
  • Onboarding — a fresh workspace always has an obvious next action.

P3 Headline features & power tools shipped

Milestone: the CS-specific superpowers that justify a custom app are real.

  • PDF import as reference — pages render alongside the note for manual transcription; no OCR, no external binaries.
  • Export to PDF — via the WebView's own print pipeline, with a dedicated print stylesheet.
  • Connections graph — Ctrl+G, a force-directed view of notes linked by [[links]] and shared tags.

P4 PDF → Markdown pipeline shipped, frozen

The brief's flagship feature. Milestone: drop an exercise sheet in and start writing solutions into it as real text.

No OCR. A typeset PDF carries its own embedded text layer — pdfium-render hands over exact glyph geometry and font metrics for free. Structure reconstruction became deterministic geometry, not machine learning.

  • Structure from geometry — headings, paragraphs, lists, and monospace code blocks reconstructed from font size, baseline, and gap analysis.
  • Real LaTeX, not images — maths regions are rebuilt as editable $…$ / $$…$$ by classifying which maths font each glyph came from (variable, relation, blackboard bold…).
  • 2D layout reconstruction — matrices, piecewise (\cases) functions, stacked and ruled fractions, operator limits, and tables all rebuild correctly, closed as a complete set.
  • Scanned-PDF fallback — a near-empty text layer is detected up front and routed to Pages mode instead of producing a garbage note.
  • Exercise splitting — "Split Into Tasks" turns a sheet into Task N / Solution pairs, each solution carrying its own handwriting canvas; "add next task" appends the next one.

Frozen against a 10-document regression corpus — a new bug earns work only if it's whole-document or recurs across two documents. Verified real-world, not synthetic: every fix traces to an actual coursework PDF.

P5 Versioned workspaces / Git automation shipped

Milestone: my notes commit themselves, in both kinds of repo. The next tier of P0's data safety — a commit is a recoverable backup.

Two modes with different defaults: a notes-only workspace pushes automatically; a workspace living inside a code repo (e.g. notes/ in a coursework project) commits but never auto-pushes, and every Git command is pathspec-scoped so it can't touch your other work.

  • Repo detection — classifies notes-only vs. code-repo on open; opt-in, never commits without an explicit yes.
  • Batched auto-commit — one commit per idle window, never per-save; backs off quietly on a mid-rebase/merge/detached-HEAD repo rather than ever repairing it.
  • Push policy — notes-only pushes after commit (configurable); a code-repo workspace cannot push through any UI path, enforced twice over.
  • Fast-forward-only pull — fetches on open; a clean fast-forward is silent, a diverged history stops and shows the ahead/behind counts instead of guessing.
  • One-click repo creation — git init plus the documented .gitignore, with an optional private GitHub remote via gh.

P6 STEM authoring shipped

Milestone: writing maths, proofs and algorithms is faster here than anywhere else. All seven tasks done — nearly everything reuses the existing Callout node rather than inventing new block types.

  • Proof & theorem blocks — Theorem / Lemma / Corollary / Proof / Definition / Example, numbered, reachable from /; a Proof block appends a CSS-only ∎.
  • Collapsible sections — presentation-only by design: toggling never dirties the buffer or triggers a P5 auto-commit for a view-state click.
  • Algorithm blocks — Complexity / Pseudocode / Implementation / References slots, the same Callout machinery as proof blocks.
  • Templates — a templates/ folder with placeholder substitution ({{date}}, {{title}}, any {{name}}); the P4-3 exercise-sheet layout ships as the first one.
  • Equation snippets — /gradient → \nabla f(x), a live dropdown inside the maths edit box itself.
  • Outline panel — Ctrl Shift O, current note's headings with scroll-tracked highlighting.
  • Cross-references — writing Theorem 3.2 in prose resolves to the numbered block it names and jumps there on click.
  • Search refinement — folder: / tag: / type: filters compose with free text; recent searches persist per workspace.

A stream of other editor nodes (block handles, dividers, alignment, highlight, HTML embed, sub/superscript, note images) shipped alongside this phase with no roadmap task behind them — see Planning notes.

P7–P8 IDE integration & embedded terminal shipped

Milestones: notes and code are one workflow and claude runs against the open note without leaving the app.

P7 — IDE integration

  • Code deep links — src/main.cpp:58 in note text is clickable, opening the configured editor at that line.
  • "Open in IDE" on code blocks — a block whose first line names its own source path gets a one-click launch.
  • Project awareness — open a code repo directly as a workspace (dependency folders excluded from the scan); optional notes/ scaffold on request only.

P8 — Embedded terminal

  • PTY-backed pane — Ctrl+\`, rooted at the workspace, survives being hidden.
  • Active-note awareness — the open note's path is an env var and a one-key insert, so claude (or any CLI) can act on exactly what you're looking at.

Notes for planning further features

Where the open threads actually are, if you're deciding what to scope next.

decision Spaced-repetition storage

The one blocking decision left on the board — not refactorable later, since it determines what happens to every card when a note is renamed. Inline HTML comment beside each card is the leading option (<!-- sr due=… ease=… interval=… -->): survives renames/moves/Git with no key tracking, and merges as readable text under P5's auto-commit/push, unlike a JSON sidecar. Decide before writing any P9-3 code.

overdue Split-pane editing

Deferred with "reconsider at P4" back when P4 was still open — P4, P6, and most of P9 are now behind it and it hasn't been revisited. Worth an explicit decision (build it, or formally re-defer) rather than leaving it drifting.

gap Off-book editor nodes

Several TipTap nodes (block handles, dividers, alignment, highlight, HTML embed, sub/superscript, note images) shipped with no roadmap task behind them — a real "Notion parity" thread running alongside P6/P9 that isn't currently named or tracked anywhere.

sequencing Workspace dashboard is the last P9 task on purpose

It has nothing of its own to show — every section reads state another task already produces (tasks, cards, Git status). Spaced repetition (P9-3) needs to land first, or the Study section has nothing to display.

infra e2e coverage now exists — use it

WebdriverIO + tauri-driver drives the real compiled app with screenshot verification, and CI runs it on every push. Two real, otherwise-invisible bugs (an outline-panel freeze, a stale-index crash in formula generation) were caught this way rather than by unit tests. Any new user-facing feature should get a spec here going forward.

frozen PDF pipeline re-entry bar

P4 is closed. It reopens only when real coursework produces a document that fails the "faster than transcribing by hand" bar — not from hunting for edge cases.
